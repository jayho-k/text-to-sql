# Chapter 00. 준비 단계 용어집

- 작성일: 2026-11-08.
- 범위: 디렉터리와 역할 문서를 읽는 데 필요한 용어. 실제 구현 규격을 정의한 문서는 아니다.

| 용어 | 쉬운 뜻 |
|---|---|
| planning | 목표를 위한 행동 순서·실행 조건을 정하는 일 |
| decomposition | 문제를 하위 문제로 나누고 결과를 다시 합칠 구조를 정하는 일 |
| rewriting / rewrite | 목적에 맞게 질문·검색어·문장 등의 표현을 바꾸는 일 |
| LLM | 대규모 언어 모델. 문맥을 받아 텍스트·도구 호출을 생성 |
| prompt | 모델에 전달하는 지시·예시·문맥 |
| strategy | 프롬프트·호출·분기·종료를 연결하는 방법별 알고리즘 |
| contract | 구성 요소가 주고받는 입력·출력·상태의 약속 |
| Deep Agents | 사용자가 사용하는 에이전트 실행 기반. 실제 버전·구성은 미확인 |
| SDK / API | 개발을 돕는 도구 묶음 / 프로그램 간 호출 규약 |
| integration | 독립 구현한 방법을 실제 실행 기반·도구에 연결하는 계층 |
| unit test | 실제 외부 모델 호출 없이 특정 계약·분기·상태를 검사하는 테스트 |
| live test | 실제 모델·도구에 연결해 동작을 확인하는 테스트. 비용·실행 조건을 기록 |
| baseline | 성능 비교의 출발점인 기준선 |
| evaluator | 정답·의미 보존·과업 성공 등을 판정하는 구성 요소 |
| embedding | 텍스트의 의미적 특성을 수치 벡터로 표현한 것 |
| DAG | 방향이 있고 순환이 없는 의존성 그래프 |
| trace | 입력·출력·도구 결과·상태·비용 등 실행 기록. 비공개 내부 사고를 뜻하지 않음 |
| run ID | 실행별 기록을 구별하는 식별자 |
| MIPRO / GEPA | 평가를 통해 지시·예시 또는 실행 피드백 기반 프롬프트 후보를 개선·선택하는 방법 |
| Git / .gitkeep | 변경 이력을 관리하는 도구 / 빈 디렉터리를 보존하기 위해 넣는 관례적 파일 |

방법별 상세 개념·원출처는 [기존 구현 분류 조사](../../../.codex/research/planning-decomposition-rewriting/10_prompt_code_architecture_classification.md)를 참고한다.
